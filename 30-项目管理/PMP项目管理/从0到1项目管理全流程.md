# 从 0 到 1：项目管理全流程

> 把 PMP 十大知识领域重新编排成「一个项目从无到有」的一条时间线：**先想清楚 → 立项 → 规划 → 执行 → 监控 → 收尾**。既是一份备考总览，也是一份面试用的「项目怎么推进」话术骨架。细节回到 [[知识体系]]、[[敏捷方法]] 查。

## 主线全景图（0 → 1）

```
需求评估 → 商业论证 → 项目章程（立项授权）
  → 识别干系人
  → 规划（范围→进度→成本→质量→资源→沟通→风险→采购→相关方 → 项目管理计划）
  → 执行（按计划干活，产出可交付成果）
  → 监控（绩效 + 变更，贯穿全程）
  → 收尾（内部核实 → 外部验收 → 移交 → 总结教训）
```

一句话：**先证明「值得做、能做」，再拿到「授权」，再画好「作战地图」，再「干活 + 盯偏差」，最后「验收 + 复盘」。**

---

## 第〇步：先想清楚「值不值得做」

动手之前先过三道闸：

1. **需求评估**——搞清楚业务到底需要什么，找到商业机会（做什么项目、创造什么成果）。
2. **商业论证 + 效益管理计划**——分析怎么做、值不值得做，两个原则：
   - 可行性（能不能做到）
   - 价值（能不能赚到钱）
   - 没有可行性 → 不干；有可行性 + 有价值 → 可以干；有可行性但低价值/没价值 → 不干。
3. **立项**——确认可行、有价值，才投入资源资金。

> 面试话术：拿到一个想法，我第一反应不是「怎么干」，而是「值不值得干、能不能干」——先做需求评估和商业论证，砍掉没有可行性和价值的伪需求，避免团队白干。

**三个基本概念（面试常问）：**

- **项目 = 为创造独特产品/服务/成果而进行的临时性工作**，三大特性：独特性、临时性、渐进明细性。
- 渐进明细 ≠ 范围蔓延：渐进明细是越做越清晰（好事）；范围蔓延是没人管的范围变化（坏事）。
- 项目 vs 运营：项目做完即结束（临时、独特）；运营持续重复产出（持续、标准化）。

---

## 第一步：启动——拿到授权，站上赛道

两件大事：

### 1. 项目章程（正式启动）

- 章程代表项目**正式启动**，代表项目经理的**正式授权**，授权我们动用组织资源。没有章程，这件事就不合法。
- **章程谁爱写谁写，但一定要发起人签字、认可。**
- 制定章程的输入包括**组织过程资产**——比如产品有问题，先翻历史记录、经验教训，看之前类似项目出问题的原因是啥。

### 2. 识别干系人（先于规划，尽早做）

- 核心就两个词：**分析 + 分组（排序）**——事分轻重缓急，人分三六九等。
- 工具：权力/利益方格、干系人立方体、凸显模型（权力 + 紧迫性 + 合法性）。
- 输出**干系人登记册**三要素：① 身份信息 ② 评估信息 ③ 分类（分组排序）。
- 越早识别越好、尽量别漏；出现新干系人 → 先更新登记册 → 再做分析。

> 面试话术：项目启动我先干两件事——拿到章程授权，把干系人一个不漏地识别出来。因为干系人是「需求之源」也是「阻力之源」，漏掉一个，后面需求、沟通、风险都会埋雷。

---

## 第二步：规划——把想法画成一张可执行的作战地图

**核心逻辑：范围是根基，需求是万恶之源。** 需求一变，范围就变，资源、成本一路连锁。所以规划先定范围，再定其他九个领域，最后汇成一份项目管理计划。

### 2.1 范围：做且仅做

1. **规划范围管理**：出范围管理计划 + 需求管理计划（怎么收集需求、谁说话好使、谁优先级高）。
2. **收集需求**：输出需求文件 + 需求跟踪矩阵（往前追章程目标、往后关联到成果，做到价值交付）。
   - 工具口诀：**亲和图做分组，名义小组做排序，说不清楚就观察，确认需求用原型。**
3. **定义范围**：写范围说明书五要素——① 产品范围 ② 项目范围 ③ 可交付成果 ④ 验收标准 ⑤ 除外责任（画边界）。
4. **创建 WBS**：把大成果拆成小成果，拆到合适颗粒度。
   - 原则：**100% 规则**（不多不少）、**8~80 小时**、最底层工作包/上一级控制账户、近期详细远期粗略（滚动式规划）。
5. **范围基准 = 范围说明书 + WBS + WBS 词典**，交有权利的相关方审批。

> 面试话术：范围管理我抓两个字——「边界」。做且只做，防止两件事：**范围蔓延**（越做越多没人管）和**镀金**（擅自加功能，画蛇添足）。

### 2.2 进度：把工作排成一条可算的时间线

1. **定义活动**：从 WBS 最底层工作包拆出具体活动（how）。
2. **排列活动顺序**：紧前关系绘图法（PDM）画网络图；依赖关系（强制/选择、内部/外部）；提前量/滞后量。
3. **估算活动资源 + 持续时间**：类比估算（快但粗略）、参数估算（算）、三点估算（(乐观 + 4×最可能 + 悲观) ÷ 6）、自下而上（没把握时拆细汇总）。
4. **制定进度计划**：关键路径法找最短工期；资源优化（资源平衡会改关键路径、资源平滑不会）；实在来不及 → 进度压缩（赶工 = 加钱、快速跟进 = 串改并）。
5. 经审批的进度计划就是**进度基准**。

> 面试话术：排计划我认「关键路径」——项目最短工期由最长的活动链决定，要压缩就**向关键路径要时间、向非关键路径要资源**。延期了优先赶工（花钱）或快速跟进（冒险），而不是盲目加人（收益递减）。

### 2.3 成本：估钱、定预算、留储备

- 估算成本（人、天不同，成本不同）。
- 汇总成预算：**成本 + 应急储备（已知风险） = 成本基准；成本基准 + 管理储备（未知风险） = 资金需求（项目预算）**。
- 直接成本（项目组承担）vs 间接成本（公司收管理费分摊）。

### 2.4 质量：预防为主

- 好的质量是**规划、设计**出来的，不是检查出来的 → 规划质量管理先行。
- 质量三过程分工：规划（定规矩）→ 管理质量（过程合规，做审计，能减少缺陷）→ 控制质量（结果合格，做检查，只能亡羊补牢）。

### 2.5 资源：权责利说清楚

- **RACI 矩阵**：R 执行、A 问责（一个工作包只能一个 A）、C 咨询、I 知会——**每件事必须有一个 A**，平时民主、谈不拢时由 A 拍板，防止「三个和尚没水喝」。
- 团队章程（团队自己定效果最好）+ 资源管理计划（培训/团建/辞退/奖励的游戏规则）。

### 2.6 沟通：约定好怎么传递信息

- 规划沟通管理：沟通需求分析 + 沟通风格评估（用对方喜欢的风格）。
- 沟通管理计划要点：谁在什么时间、以什么方式、把什么信息、以什么详细程度、发给谁，怎么上报、怎么确认收到。
- 渠道多了要简化，防止信息失真。

### 2.7 风险：先识别、再排序、后应对

1. 规划风险管理（概率影响矩阵、RBS）→ 2. 识别风险（登记造册）→ 3. 定性分析（排优先级）→ 4. 定量分析（大项目才做）→ 5. 规划应对 → 6. 实施应对 → 7. 监督。

- **威胁**：回避、转移、减轻、接受、上报；**机会**：开拓、分享、提高、接受、上报。
- 口诀：自己做饭不好吃就**转移**（叫外卖）；系统升级有风险就**回避**（不升级）；超出权力就**上报**。

### 2.8 采购：按范围明确程度选合同

- 范围明确 → 总价合同；范围不明确 → 成本补偿合同；范围不明确但要快 → 工料合同。
- 周期长、物价汇率波动 → 加 EPA 条款（经济价格调整）。

### 2.9 相关方：看态度、定策略

- **相关方参与度评估矩阵**（五级）：不知晓 → 抵制 → 中立 → 支持 → 领导。
- 对比「当前参与度」和「期望参与度」定策略：张三现在反对、希望他支持；李四口头支持、希望他有行动。

### 2.10 汇成项目管理计划

把上面所有子计划打包，交关键干系人审批——这是后面执行、监控的唯一依据。

> 面试话术：规划阶段我不会一头扎进细节，而是按「范围 → 进度/成本 → 质量/资源/沟通/风险/采购/相关方」的顺序走，最后合成一份计划。因为范围决定后面一切，顺序错了会返工。

## 第三步：执行——把计划变成成果

1. **指导与管理项目工作**：按计划干活，产出可交付成果。
2. **建设团队**：塔克曼阶梯——形成（指挥）→ 震荡（教练）→ 规范（支持）→ 成熟（授权）→ 解散。成员成熟就授权，技术弱的就强化监督。
3. **管理团队**：人的问题 = 能力 + 态度，该培训培训、该指导指导（治病救人）。
4. **管理沟通**：执行沟通计划，输出项目沟通记录（留痕，避免口说无凭）。
5. **实施采购**：招标 → 投标 → 评标 → 中标 → 签约。

> 面试话术：执行阶段我是「服务型领导」——把决策权下放给成熟团队，我自己盯协作、扫障碍。**权力可以交接，责任不能转移**，出了事还是我兜底。

---

## 第四步：监控——贯穿全程的两件事：绩效 + 变更

监控不是最后才做，而是**从启动到收尾一直跟着跑**。

### 1. 绩效监控（看偏差）

- 挣值管理（EVM）核心三个数：**PV**（该干的活）、**EV**（干完的活）、**AC**（花的钱）。
- SV = EV − PV（进度偏差）、CV = EV − AC（成本偏差）；SPI、CPI 大于 1 好、小于 1 差。
- 收尾预测：BAC（总预算）、EAC = AC + ETC（完工估算）、TCPI（剩下多少事 ÷ 剩下多少钱）。

### 2. 变更控制（管变化）

所有变更都走同一条流程：

```
变更请求 → 记录（变更日志）→ 综合分析评估影响 → 决策 → 更新计划文件 → 通知干系人落实
```

- 没有变更请求，不开展这个流程；项目经理对变更控制负最终责任。
- **涉及基准的变更 → CCB 审；不涉及基准的变更 → 项目经理直接批。**
- 变更没人管 → **范围蔓延**。

### 3. 各领域监控

- 控制范围/进度/成本（绩效 + 变更）
- 控制质量（QC，团队先自查再验收）
- 监督风险（风险审计看过程、风险审查看措施）
- 监督沟通、监督相关方参与（跟踪态度变化、调整策略）
- 控制资源（防浪费）、控制采购（看绩效、管变更）

> 面试话术：项目过程中我脑子里始终挂着两根弦——「进度成本有没有跑偏」和「变化有没有人管」。跑偏了看 EVM 找原因，变化了走变更流程，绝不拍脑袋加需求。

---

## 第五步：收尾——验收、移交、复盘

1. **先内部核实，再外部验收**：

```
可交付成果 → 控制质量（团队自查测试）→ 核实的可交付成果 → 确认范围（客户/发起人验收）→ 验收的可交付成果 → 结束项目或阶段（移交）
```

- 别把半成品直接丢给客户（否则返工 + 客户满意度下降 + 外部失败成本）。**站好最后一班岗。**

2. **结束项目或阶段**：移交成果，关闭采购（钱货两清）。
3. **总结经验教训**：采购审计、质量审计、风险审计都是「回顾过程」，目的是**未来项目不遇到同样的问题**。
4. **效益跟踪**：项目结束 ≠ 效益到手，交给效益管理计划持续跟踪。

> 面试话术：收尾我会做三件事——先自查再交付（不砸招牌）、把文档和知识移交归档（不丢资产）、开复盘会沉淀教训（同一块石头不绊两次）。

## 一条主线串起来（记忆口诀）

**先证明值不值 → 再拿到授权 → 画好作战地图 → 按图干活 → 全程盯偏差管变更 → 验收复盘。**

对应的 PMBOK 五大过程组：启动 → 规划 → 执行 → 监控 → 收尾；背后是十大知识领域、49 个过程，以及「多快好省 + 六大制约（范围、进度、成本、质量、资源、风险）」的目标体系。

## 面试速览：高频问题 → 回答要点

| 面试官问 | 回答要点（对应主线） | 可用比喻 |
| --- | --- | --- |
| 讲讲你负责的一个项目 | 按 STAR + 这条 0→1 主线走：背景/目标 → 我怎么规划 → 怎么执行 → 遇到什么问题 → 怎么收尾 → 结果 | — |
| 项目怎么从 0 到 1 推进 | 先商业论证证明值得做 → 章程授权 → 范围打底 → 进度成本质量资源沟通风险规划 → 执行 + 监控 → 验收复盘 | 「先证明值不值，再画地图再干活」 |
| 需求老变怎么办 | 走变更控制：记录→评估→决策→更新→通知；敏捷里找 PO 排序 | 「变更不可怕，可怕的是没人管」 |
| 干系人不配合怎么办 | 先分清态度问题还是沟通问题；态度问题管参与（评估矩阵五级）、沟通问题换方式 | 「先说对方想听的，再说自己想说的」 |
| 团队起冲突怎么办 | 五策略：缓解/撤退/妥协/强迫/合作，看情况用 | 「心甘情愿地输也是妥协」 |
| 项目延期/超支怎么办 | 找关键路径做进度压缩（赶工/快速跟进）；EVM 看偏差和趋势 | 「向关键路径要时间，向非关键路径要资源」 |
| 风险怎么管 | 识别→定性排序→应对（威胁回避/转移/减轻/接受/上报） | 「做饭不好吃就叫外卖（转移）」 |
| 传统 vs 敏捷怎么选 | 需求×方案矩阵：都确定→预测；需求或方案不确定→迭代/增量；都不确定→敏捷 | 「网站要兼容多浏览器 → 迭代」 |
| 你怎么保证质量 | 预防为主：规划 + 管理质量（过程）+ 控制质量（结果）；先自查再交付 | 「厨师不洗手菜再好吃也不合格」 |
| 怎么向上汇报 | 按沟通管理计划：对的人、对的时间、对的方式、对的详略；绩效报告 | 「有人看结论、有人看细节」 |
| 没有明确谁负责怎么办 | 上 RACI，每个工作包一个 A | 「三个和尚没水喝」 |
