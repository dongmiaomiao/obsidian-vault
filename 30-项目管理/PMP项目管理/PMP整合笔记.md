# PMP 整合笔记

> 由 4 份归档草稿（项目管理、PMP知识点速记、PMP项目管理知识点、PMP整合管理）去重精简而成，是 [[知识体系]] 的精简串讲版；细节与完整过程回到 [[知识体系]]、[[敏捷方法]]、[[十大知识领域速记]] 查。

## 一、核心理念

- 事事皆项目，人人为项目。
- 管理学上没有绝对的对与错，永远是找**相对最合适**的选项。

**什么是项目**：为创造独特的产品、服务或成果而进行的**临时性**工作。

- 产品（手机、汽车、房子）；服务（工作达到的效果）；成果（科研成果、核酸检测）。

**三大特性：**

1. **独特性**：没有两片相同的树叶，成果独特，有不同就有不确定性，不确定性就是风险。
2. **临时性**：有明确起止，做完就结束；临时性不适用于项目产出的成果（产品要一直用）。
3. **渐进明细性**：从高层级到底层级不断细化。⚠️ 渐进明细 ≠ 范围蔓延——范围蔓延是没人管的范围变化。

## 二、项目 vs 运营

| 维度 | 项目 | 运营 |
| --- | --- | --- |
| 性质 | 临时、独特、渐进明细 | 持续、重复 |
| 目标 | 做完即结束 | 持续产出 |
| 过程 | 不适合标准化 | 追求标准化、规范化 |

**共性：** 都服务于公司战略、都需要规划/执行/控制、都受资源资金约束；资源在两者间双向流动——启动项目从运营抽调资源，结束后带着新知识回到运营，可交付成果移交给运营。

## 三、战略 → 项目组合 → 项目集 → 项目 → 运营

1. 企业体现**商业价值** → 需要**战略计划** → 靠**项目 + 运营**落地 → 匹配战略的纳入**项目组合**。
2. 项目管理是实现战略的关键技能。

| 层次 | 关注 | 回答的问题 |
| --- | --- | --- |
| 项目组合 | 事分轻重缓急，分配人财物 | 什么是对的、优先级怎么排（做正确的事） |
| 项目集 | 协调多个有依赖的事 | 有依赖的事怎么一起搞定 |
| 项目 | 完成任务 | 单件事怎么做好（把事做正确） |
| 运营 | 降本增效、持续产出 | 怎么持续、标准化产出 |

> 项目属于项目集 → 跟其他事有依赖关系；属于项目组合 → 跟公司战略有相关性。

## 四、生命周期与开发方法

**项目生命周期**：共性四阶段——开始 → 组织与准备 → 执行 → 结束。两特征：变更代价早期低后期高；风险由高到低（想办法让问题**前置暴露**）。

**产品生命周期**：研发 → 引入市场 → 上升期 → 成熟期 → 衰退期 → 退出市场（每个阶段通常含多个项目）。

**开发生命周期（开发方法）**：

| 需求 | 方案 | 采用模式 |
| --- | --- | --- |
| 确定 | 确定 | 预测型（一次搞定） |
| 不确定 | 确定 | 增量（逐步加功能） |
| 确定 | 不确定 | 迭代（循环改进） |
| 不确定 | 不确定 | 敏捷（短周期快速反馈） |
| 复杂场景 | — | 混合型（该预测的预测、该敏捷的敏捷） |

- 增量 = 加功能；迭代 = 循环改进；敏捷 = 迭代 + 增量 + 固定时间盒（≤4 周）。
- 变化不频繁、周期可较长 → 迭代/增量；需求方案都模糊、需快速响应 → 敏捷。

## 五、五大过程组与 PDCA

每个阶段重复开展五大过程组，包含十大知识领域、49 个过程。

1. **启动**：授权，输出项目章程。
2. **规划**：制定行动方案，输出项目管理计划。
3. **执行**：按计划干活，产出可交付成果。
4. **监控**：① 绩效 ② 变更。
5. **收尾**：结束阶段，总结、存档、移交。

> 五大过程组就是 PDCA（计划→执行→检查→改进）。叫外卖的例子：定计划（吃什么）→ 点餐交钱（执行）→ 看小哥到哪（监控）→ 下次货比三家（改进）。

## 六、目标与制约

**多快好省**（项目目标）：多（范围）、快（进度）、好（质量）、省（成本）；中间是范围，旁边是约束性目标。

**六大制约因素**：范围、进度、成本、质量、资源、风险——任何一项变化都会连锁影响其他项。

**十大知识领域**：整合、范围、进度、成本、质量、资源、沟通、风险、采购、相关方。

## 七、治理与启动

- **组织治理**：定组织架构 + 工作流程 + 制度规范 ≈ 权力的分配。
- **项目治理**：指导项目管理活动的框架、功能和过程 ≈ 项目上权力的分配。

**启动前三件事：** ① 需求评估（找商业机会）→ ② 商业论证 + 效益计划（可行性 + 价值，两个都成立才干）→ ③ 项目启动。阶段之间设**阶段关口**，验证是否还有可行性和价值，不行及时止损。

## 八、各知识领域串讲（一条主线）

- **整合管理**：把十大知识领域统筹起来——制定章程 → 制定项目管理计划 → 指导与管理项目工作 → 管理项目知识 → 监控项目工作 → 实施整体变更控制 → 结束项目或阶段。
- **范围管理**：做且仅做。收集需求→需求文件；定义范围→范围说明书；创建 WBS→WBS 词典；**范围基准 = 范围说明书 + WBS + WBS 词典**。
- **进度管理**：时间够不够。定义活动（从工作包拆活动）→ 排列活动顺序（PDM 画网络图、依赖关系、提前量/滞后量）→ 估算持续时间（先估资源再估时间）→ 制定进度计划（甘特图、关键路径、资源优化、进度压缩）。
- **成本管理**：钱够不够。估算成本（活动维度）→ 制定预算（汇总成本 + 应急储备 = 成本基准；成本基准 + 管理储备 = 资金需求）。
- **质量管理**：好的质量是规划设计出来的。规划质量管理（定规矩）→ 管理质量（过程合规：质量保证 / 过程改进 / 产品设计）→ 控制质量（结果合格：检查测试）。先内部质控、再外部验收，别把半成品直接丢给客户。
- **资源管理**：规划资源（定架构、责任分配）→ 获取资源（职能经理 → 其他 PM → 供应商）→ 建设团队（塔克曼：形成/震荡/规范/成熟/解散）→ 管理团队（处理冲突）→ 控制资源（不浪费）。
- **风险管理**：识别 → 定性分析（排优先级）→ 定量分析（大项目才做）→ 规划应对 → 实施应对 → 监督。
- **采购管理**：规划采购（招标文件 / SOW / 供方选择标准 / 预算）→ 实施采购（招标 → 投标 → 评标 → 中标 → 签约）→ 控制采购（跟踪绩效、钱货两清）。
- **干系人 vs 沟通**：沟通侧重信息传递，干系人侧重态度/参与度，且**沟通前先分析干系人态度**。听不清 → 沟通问题；不愿听 → 态度问题。

## 九、变更管理

计划之外的都是变更。流程：变更请求 → 记录（变更日志）→ 综合分析影响 → 决策 → 更新计划文件 → 通知干系人落实。

- 涉及基准的变更 → CCB 审；不涉及基准 → 项目经理直接批。
- 项目经理对整体变更控制负最终责任；没人管的变更就是范围蔓延。

## 十、风险管理

**过程顺序**：规划风险管理 → 识别风险 → 定性分析 → 定量分析 → 规划应对 → 实施应对 → 监督风险（审计看过程、审查看措施）。

**应对策略**：威胁——回避、转移、减轻、接受、上报；机会——开拓、分享、提高、接受、上报。

- 转移：做饭不好吃就叫外卖；回避：系统升级有风险就不升级；主动接受：提前备应急计划/储备；被动接受：纯躺平；上报：超出权力范围。

## 十一、冲突管理

看情况选策略：太激烈 → 缓解；没条件 → 撤退/回避；对方固执 → 妥协；太犹豫 → 强迫（用权力）；最好 → 合作。

- 强迫 vs 回避：回避没给出决策结果，强迫是"你们都错了，就我对"。
- 冲突多次出现 → 问题升级，找更高层沟通。
- RACI 每个层级必须有一个 A：平时民主，谈不拢时由 A 拍板，防止工作卡住。

## 十二、相关方管理

**三板斧：** ① 识别相关方（分析 + 分组排序，输出登记册）→ ② 规划参与（看态度、定策略，参与度五级：不知晓 → 抵制 → 中立 → 支持 → 领导）→ ③ 规划沟通（不要上来就沟通）。

**权力/利益方格**：高权高利=重点管理；高权低利=令其满意；低权高利=随时告知；低权低利=监督。

## 十三、沟通管理

重点是**规划沟通管理**：沟通需求分析 + 沟通风格评估（用对方喜欢的风格）。渠道随人数增加而变多，要简化渠道、防止信息失真。

## 十四、资源与团队

- 获取资源三渠道（优先级）：职能经理（优质资源）→ 其他项目经理（稀缺资源）→ 供应商。
- 有人技能不足 → 看资源管理计划（培训/换人/辞退/调岗）。
- 权责不清 → RACI 矩阵；人员离职 → 及时更新组织知识库，做好知识转移。
- 集中办公（沟通好、成本高）vs 虚拟团队（成本低、凝聚力差）。

## 十五、领导力与管理理论

- 领导力就是让别人有主动性——以身作则；涉及权力 → 想到责任分配矩阵（民主 + 独裁）。
- **光环效应**：业务强 ≠ 管理强。**Z 理论**：关注员工成长、健康、福利。
- **X/Y 理论**：X=人性本恶严格管；Y=人性本善宽松管。
- **马斯洛**：尊重各层次需求。**弗鲁姆期望理论**：员工会分析可行性和价值。
- **赫兹伯格双因素**：保健因素防止不满意（工资）；激励因素促成满意（成就/认同/责任/晋升）。

## 十六、敏捷速记

- **四大会议**：迭代规划会（做什么）、迭代评审会（看成果、要反馈）、回顾会（看过程、改进）、每日站会（了解情况、问题早暴露）。
- **需求排序工具**：MoSCoW（必须有/应该有/可以有/不能有）、卡诺模型、扑克估算、理想人天、T 恤尺码。
- **故事点无法跨团队比较**；质量不可协商；WIP 在制品限制——用最小代价试错。
- 其他：停车场（挂起议题）、西瓜项目（及时跟踪）、技术债务（临时方案要重构）、燃尽图/燃起图。

## 十七、工具与图表速记

- **艾森豪威尔矩阵**（优先级）：重要×紧急——重要紧急马上做、重要不紧急规划做、不重要紧急授权做、不重要不紧急忽略。
- **需求收集**：需求不确定 → 原型法；表述不清 → 观察法；亲和图做分组、名义小组做排序。
- **进度压缩**：赶工（加钱加资源）、快速跟进（串改并）；前提是先找关键路径。
- **可视化图表**：燃尽图（剩余工作量）、燃起图（总故事点）、散点图（两变量相关性）。

## 十八、其他要点

- **先有章程后有计划**：章程代表正式授权，谁爱写谁写，但一定发起人签字；没有章程这事不合法。
- **文化意识**：不同国家、民族、宗教、信仰，鼓励文化意识，减少误解冲突。
- **总结经验教训**：采购/质量/风险审计都是回顾过程，目的是未来项目不遇到同样问题。
- **PMO**：关注项目方法、标准、规范、流程的制定，工作重心是方法论。
- **问题解决流程**：定义问题 → 分析原因 → 制定方案 → 选择方案 → 执行方案 → 跟踪效果；问题再现要分析原因，防止治标不治本。
