# 工具与技术

> 汇总各知识领域常用的工具与技术，配合 [[知识体系]] 一起看；本笔记由原始草稿重构而来，保留了口语化讲解。

## 一、需求收集与分析

### 收集需求的工具

- **专家判断**：专业的事找专业的人。在某个方面有知识、技巧、经验、受过培训，就是这个领域的专家，让专家提出合理化建议，确保项目的合理性、可行性。
- **头脑风暴**：发散思维，只要思想不滑坡、办法总比困难多；集思广益，先创新、再评价。
- **访谈**：面对面沟通聊天。
- **焦点小组**：有主持人、有主题，防止偏离会议主题。
- **问卷调查**：人不在同一个地方，就发问卷。
- **标杆对照**：参考、借鉴别人的最佳实践（也就是「抄」）。
- **文件分析**：分析用户的业务文档，更好地了解业务流程、涉及哪些数据，从而挖掘需求。
- **亲和图**：做分组——排序之前先分组，以便在同一分组内排优先级。
- **名义小组**：做排序——临时小团队做优先级排序。
- **观察与交谈**：说不清楚就观察，察言观色是主观的；不愿意说、说不清楚时，还需通过交谈来确认需求。
- **原型法**：确认需求——先做出该产品的模型，征求对需求的反馈，不对就改，不断循环。
- **故事板**：一种原型技术，用一系列图像/图示展示顺序或导航路径，确认需求。

> 口诀：亲和图做分组，名义小组做排序，说不清楚就观察，确认需求用原型。

### 需求排序工具

**QFD（质量功能展开）**：制造业生产越多成本越低，利润越薄，持续产出相同品质的产品才有利润；但生产出来的东西客户万一不喜欢、不愿花钱买就砸了。所以把需求分成三大类：

1. **基本需求**：一定要具备的，没满足客户就不会花钱买。
2. **期望需求**：用户会明确表达的期望，满足可提高买单欲望，不满足不一定买单。
3. **意外需求（惊喜）**：用户想不到的功能属性，可能提高买单意愿。

**KANO（卡诺模型）**：在 QFD 三类基础上又总结出 **无差异需求**——有它没它无所谓。不同人群需求不同：张三的需求在李四眼里是无差异需求，李四的意外需求在王五眼里反而可能是基本需求。对不同人群的需求分类/分组，决定需求优先级。还有 **逆向需求**：实现它可能引起用户不满、满意度下降，但还不能不做——我们认为讨厌的东西，在某些人眼里是有用的。

**MoSCoW（莫斯科）**：把需求分四大类——必须有（M）、应该有（S）、可以有（C）、不能有（W）。

**用户故事**：传统项目收集需求得到又重又多的需求文件；敏捷轻装上阵，把需求变成一张张小卡片，每张卡片三句话把需求说清楚——① 角色、② 要实现什么目标、③ 动机（期望获得什么利益）。深入挖掘他为什么要这个东西，以便分析需求的有效性。

## 二、冲突管理

冲突不可避免，想办法减少冲突的出现和发生。冲突来源：资源稀缺、进度优先级排序、文化、工作风格等。用团队基本原则、团队规范及成熟的项目管理实践（如沟通规划和角色定义）可减少冲突数量。

冲突未必是坏事，成功的冲突管理能提高生产力。如意见分歧成为负面因素，最好私下处理——负面影响最小化、正面影响最大化。

**五种解决方法：**

| 策略 | 特点 |
| --- | --- |
| 撤退/回避 | 没有能力解决就撤退，谁有能力找谁解决；退出、搞不定 |
| 缓和/包容 | 情绪不好、气氛紧张、生气暴躁时，先让对方心平气和，不解决冲突 |
| 妥协/调解 | 折中、临时/暂时部分解决，双方需求没完全满足，有一定程度满意——各打 50 大板，一定程度满意是双赢、一定程度不满意是双输 |
| 强迫/命令 | 用权力强行解决，谁有权谁说了算；需当机立断，重要又紧急 |
| 合作/解决问题 | 合作态度 + 开放式对话，引导各方达成共识，双赢；重要/不紧急 |

> 对方是领导，屈从了也叫妥协，就是主动服从。

冲突管理关注想尽办法促进大家达成共识；**引导技术**关注想尽办法减少冲突。不同人群需求不一样，看到不同人群就考虑引导，防止产生不必要的冲突。有效引导的研讨会有助于参与者建立信任、改进关系、改善沟通，从而达成共识。

**投票 vs 独裁**：投票是民主（大家开心满意）；独裁让一些人不开心但效率高（紧急情况做正式决策）。尽可能合作达成共识。

## 三、会议与文档

- **会议管理**：会前定会议目标、议程，准备会议资料，确定时间、地点、人物；会中按议程 12345，别偏离主题、别打乱秩序；会后形成会议纪要、落实到人。根据目标定计划，根据计划定议程，确保会议开始和结束日期，不能遥遥无期。
- **核对单**：逐项核对检查章程的正确性、完整性，逐项检查计划的正确性、完整性。
- **开工会议（开题会）**：项目作战计划已完成、各方达成共识后，落实执行前开的会——把计划做成 PPT，让执行计划的人清晰知道个人目标、团队目标、什么时间做什么事、项目目标、各关键方角色职责。
- **启动会**：按项目章程制定行动方案、把章程做成 PPT，让大家知道有什么项目、宏观要求、目的目标、成功标准、退出标准、项目经理是谁，以便支持项目经理打造可行的作战计划。
- **项目管理信息系统、工作授权系统**：确保干活有序，确保正确的组织在正确的时间、按合理顺序干活。

## 四、知识管理与信息管理

- **知识管理**：防止知识流失，学以致用的前提是「有的学」——想办法把知识显性化、隐性化、体系化，让大家交流互动，在实际工作中产生源源不断的新隐性知识。知识管理侧重**互动**，通过交流加强理解。
- **信息管理**：侧重像百度百科一样的搜索查询。
- 知识管理确保**理解的一致性**——多沟通、多讨论、多互动才能更好理解。
- 面对面互动有利于建立知识管理的信任关系；信任关系建立后，可用虚拟互动维护。
- **根本原因分析**：防止治标不治本，找出根本原因才能对症下药。因果图（鱼骨图、石川图、why-why 分析图）用来找原因。
- **偏差分析**：用理想（计划）和现实（实际）做比较，看是否有出入；找到偏差后看是否在可接受的范围内（控制临界值）。

## 五、变更控制与配置控制

**实施整体变更控制**流程：

1. 先有变更请求；
2. 做正式记录；
3. 分析评估变更对项目产生的影响；
4. 做决定——涉及基准的变更需要 CCB 决定；不涉及基准或紧急情况下项目经理决定；
5. 拿到决定结果，更新相关计划和文件；
6. 通知干系人落实执行。

**配置控制**：就是版本管理，重点关注一个个可交付成果及各个过程的技术规范。版本管起来工作量大、是技术活，所以需要标准化、规范化可交付成果及各个过程的技术规范。

**变更控制**：更侧重变更的流程。

## 六、范围管理工具

- **定义范围**：写范围说明书——说清楚要创建什么样的产品（产品范围）、交付产品需开展什么工作（项目范围）、要交付哪些可交付成果、交付成果对应的验收标准，再画个边界，约定好**除外责任**（什么不包含在范围内）。
- **分解（创建 WBS）**：把大成果分解成小成果，工作和成果都要分解到合适大小，便于管理。原则：
  - **100% 规则**：确保不多不少、没有遗漏和多余工作（WBS 决定未来的资源、时间、成本，WBS 不正确不完整会导致在错误道路上越走越远）。
  - **8~80 小时原则**：从上向下分解、从下向上核实。
  - WBS 结构形式：① 以项目生命周期各阶段作为第二层；② 把项目和产品可交付成果放在第三层；③ 以主要可交付成果做第二层（以结果为导向）。
- **检查（确认范围）**：做验收。查就是结果、计就是过程。检查也称审查、同行审查或巡查。

## 七、进度管理工具

### 排列活动顺序

- **紧前关系绘图法（PDM，活动节点法 AON）**：约定绘图方法，用节点表示活动，直观看出先干啥后干啥。
- **确定与整合依赖关系**：① 强制的（必须的、没得选、串行）；② 选择的（有的选，取决于团队最佳实践）；③ 内部的；④ 外部的——做排列组合。
- 持续时间估算中**不包括任何提前量或滞后量**。

### 估算工具

- **类比估算**：根据历史信息直接给出估算，快但不一定准、较粗略。若以往活动本质（而非表面）类似、估算成员具备专业知识，类比就可靠。
- **参数估算**：基于历史数据和项目参数，经过计算给出结果；准确性取决于参数模型的成熟度和基础数据可靠性。
- **三点估算**：不确定与风险——最可能、最乐观（最小）、最悲观（最大）。(最乐观 + 4×最可能 + 最悲观) ÷ 6（贝塔分布）。
- **自下而上估算**：前提是已有估算结果但不可信、没把握——把当前活动拆成更小的活动分别估算再汇总；分解越细越准。
- **储备分析**：已知风险准备额外的时间或钱 = **应急储备**；未知风险、意外没认知的东西 = **管理储备**。监控过程组（控制成本/进度/风险）都要根据风险发生情况分析储备用了多少、还够不够、是否需要增加或释放。

### 进度计划与分析

- **进度网络分析**：切实可行的进度计划不可能一步到位，需反复调整——综合考虑范围、进度、成本、质量、资源、沟通、风险甚至干系人满意度，不断打磨优化，直到具有良好的可行性。
- **关键路径**：完成工作需要的最短时间，是项目中最长的活动顺序。关键路径不一定只有一条，且随时可能变化——控制进度时要跟踪关键路径状态，判断能否按期交付。总浮动时间为 0（正值很灵活，负值很紧张、来不及）。
- **关键路径法**用于规划和控制两个过程组：规划时制定可行进度计划；控制时跟踪关键路径状态。
- **资源优化技术**：**资源平衡**往往导致关键路径改变；**资源平滑**不会改变关键路径（可能无法实现所有资源优化）。
- **向关键路径要时间，向非关键路径要资源**：把非关键路径的活动资源挪到关键路径上，让关键路径工期变短、尽早交付；非关键路径延长不一定会改变关键路径。
- **假设情景分析**：分析进度计划万一遇到障碍是否影响最终交付日期，如会则提前给出应对策略——进度内部的风险分析。
- **进度压缩**：**快速跟进**（串改并、高风险、同一时间开展多个活动、没钱）；**赶工**（高成本、增加额外资源、加班加急、不差钱）。

### 挣值管理（EVM）

- **PV（计划价值）**：某个时间点应该完成的工作（随时间水涨船高）。PV 的总和 = 绩效测量基准 PMB = 完工预算 BAC。
- **EV（挣值）**：干多少活挣多少钱，已完成工作的经批准的预算。
- **AC（实际成本）**：干活花出去的钱，没上限，为实现 EV 花的任何成本都计入。
- **SV（进度偏差）= EV − PV**；**CV（成本偏差）= EV − AC**。
- **SPI（进度绩效指数）= EV ÷ PV**；SPI<1 已完成工作量未达计划，SPI>1 超额完成（因 SPI 测总工作量，还需单独分析关键路径绩效）。
- **CPI（成本绩效指数）= EV ÷ AC**：分析过去是少花钱多办事还是多花钱少办事、成本节约还是超支。
- **BAC（完工预算）**：计划完成工作需要的钱。
- **ETC（完工尚需估算）**：完成剩余工作还需多少钱。
- **EAC（完工估算）= AC + ETC**：已花出去 + 还需要的，做的趋势分析。
- **VAC（完工偏差）= BAC − EAC**。
- **TCPI（完工尚需绩效指数）**：剩下多少事 ÷ 剩下多少钱。CPI<1（多花钱少办事）时，要让以后 TCPI>1（少花钱多办事）；CPI>1 时允许以后 TCPI<1（允许铺张浪费一丢丢）。

## 八、质量管理工具

- **质量成本**：预防成本（提高、防止出错）、评估成本（降低、做检查测试）、内部失败（减少、自己发现并修复缺陷）、外部失败（杜绝、客户发现所产生的成本）。一致性成本 = 预防成本 + 评估成本（为了后面不出错）；非一致性成本 = 内部失败 + 外部失败（出错了才产生）。所以先质控再验收，先自己检查测试没问题了再正式验收。
- **因果图**（鱼骨图、石川图、why-why 分析图）：识别问题的主要原因或根本原因，对症下药。
- **直方图**：展示数字数据的条形图，有图有真相，直观。
- **核查表（计数表）**：合理排列各种事项，记录缺陷次数。
- **帕累托图**：排序的直方图。
- **审计**（质量审计、风险审计、采购审计）：关注过程的合规性——实际过程是否符合既定的标准、政策、程序、流程、规范。分析哪做得好哪做得不好：不好的吃一堑长一智，好的发扬光大，为组织过程资产/经验教训积累做贡献。
- **面向 X 的设计**：设计产品时考虑产品方方面面，降本增效、考虑周全。
- **过程分析（管理质量）**：识别过程改进机会，检查过程期间遇到的问题、制约因素和非增值活动，看能否消灭无价值、低价值活动，提高效率、降低成本、提升质量。
- **问题解决流程**：① 定义问题（发现啥记录啥，问题日志）→ ② 识别根本原因（鱼骨图/石川图/why-why/因果图，对症下药、防止治标不治本）→ ③ 生成可能的解决方案（只要思想不滑坡、方法总比问题多，备选方案分析，方法别过于单一）→ ④ 选择最佳解决方案（考虑成本效益等因素，能民主就民主，实在不行就独裁、当机立断）→ ⑤ 执行解决方案（落实到人）→ ⑥ 验证有效性（防止死灰复燃）。
- **质量改进方法**：PDCA、六西格玛，持续改进。
- **统计抽样**：1 就是多，2 可能会对样本造成破坏。
- **控制图**：判断过程是否稳定——不稳定就超出控制上下限，认为过程失控，要分析原因、确保受控。**7 点规则**：连续 7 个采样结果都在均线同一侧（都比均线小或大），也算过程不稳定。**规格上下限**反映可允许的最大最小值：超出控制上下限但没超规格上下限，虽失控还能接受；超出规格上下限，结果不能接受。
- **流程图**：用可视化图示分析过程。
- **矩阵图、散点图**：验证两个元素是否相关；有关系再通过**回归分析**把关系变成公式/模型，以后干活省事。回归分析用于分析项目结果、不同项目之间的相互关系，变成公式模型以提高未来项目绩效。

## 九、资源与团队管理工具

### 规划资源（层级型 / 矩阵型 / 文本型）

- **层级型**：上下级关系（工作分解结构 WBS、组织分解结构 OBS、资源分解结构 RBS）。
- **矩阵型**：表格，让大家知道大事小情里的分工。
- **文本型**：说清楚每个角色、每个岗位的职责权限。
- 目的：让员工各司其职，明白要做什么、和谁配合、领导是谁，**防止三个和尚没水喝**；确保每个工作包都有明确责任人，权责利说清楚。

**责任分配矩阵（RACI）**：确保任何一项任务都只有一个人负责（A 只有一个，他来承担最终结果、来背锅）。R=执行（干活）、A=问责（出了问题谁承担最终结果）、C=咨询、I=知会。民主可能难以达成共识，需要有人承担最终责任、必要时独裁。

### 获取资源

- **谈判**：① 找职能经理（优质资源）；② 找项目经理（稀缺资源）；③ 找供应商（获取资源）。
- **采购谈判**：专业的事交给专业的人，由采购团队中拥有合同签署职权的成员主导；项目经理和团队其他成员可参加并提供协助。
- **预分派**：事先确定项目的实物或团队资源，因各种原因导致资源选择受限制。

### 团队建设与激励

- **虚拟团队**：优点降成本、资源选择面更广；缺点沟通不方便、团队意识凝聚力差。
- **集中办公**：沟通方便；成本高、资源受约束限制。
- **团队建设**：让大家尽快熟悉、互相理解、有同理心、拉近关系，达到高效自组织团队、促进人际关系。
- **认可与奖励**：只有能满足被奖励者某个重要需求的奖励，才是有效奖励。
- **培训**：成员缺乏必要的管理或技术技能时，可把技能培养作为项目工作一部分。培训成本通常算项目直接成本；如增加的技能有利于未来项目，则由执行组织（公司）承担，作为每个项目的间接成本。
- **情商**：识别、评估和管理个人情绪、他人情绪及团体情绪的能力——自评（知道自己是什么人）、自控、了解对方是什么人、采取合适言行、顾及他人感受，根据周围环境决定言行效果。

## 十、沟通管理工具

- **沟通需求分析**：防止消息满天飞，了解对方的信息诉求。沟通渠道数 = N × (N−1) ÷ 2（N 为总人数）。人多嘴杂、渠道越多沟通越复杂，要减少沟通渠道、减少信息传播途径，防止信息失真。
- **沟通模型**：发送方（编码）→ 传播途径（媒介）→ 接收方（解码）；信息传递中可能受噪声干扰导致失真。
- **沟通方法**：
  - 互动沟通：会议、电话、即时信息、社交媒体、视频会议。
  - 推式沟通：确保信息的发送（不能确保送达被理解）——信件、电子邮件、传真、播客。
  - 拉式沟通：适用于大量复杂信息或大量受众——企业内网、在线课程、经验教训、数据库/知识库。
- **沟通风格评估**：常用于不支持项目的相关方。
- **非口头技能**：通过示意、语调、面部表情等肢体语言表达意思。
- **项目报告**：发布项目绩效报告（临时汇报）。
