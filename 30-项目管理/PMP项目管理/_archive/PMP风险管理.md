# PMP 风险管理

## 规划风险管理
找到干系人，分析各方的风险偏好，把它变成客观、可量化的临界值，分成不同区间，从而得到：

- 概率影响等级定义
- 概率影响矩阵
- RBS 风险分解结构

## 识别风险
想尽各种方法找风险，最好有条理、有依据。先做规划风险，产出 RBS 风险分解结构：把风险分为不同种类，大类之下还可细分具体类别（内部风险、进度风险、外部风险等），帮助我们更全面地识别风险、避免遗漏。

代表性工具：

**1. 假设条件和制约因素分析**（制定项目章程输出的假设日志里，记录所有假设条件和制约因素）

- 假设条件：我们主观上认为它成立的事件和条件，成立与否不一定，一旦不成立会引发威胁。
- 制约因素：对我们形成制约、限制的客观条件。
- 从假设条件的不准确、不稳定、不一定或不完整，可识别出威胁（坏事）；通过清除或放松影响项目/过程执行的制约因素，可创造出机会。

**2. SWOT 分析**

- 优势 → 带来机会：提高质量、降低成本、缩短工期、提高客户满意度。
- 劣势 → 引发威胁：工期延长、成本超支、进度落后、干系人不开心、沟通糟糕、管理不到位。
- 识别组织的优势、劣势，找出优势可能为项目带来的机会、劣势可能造成的威胁。

**3. 提示清单**

以 RBS 底层的风险类别作为提示清单，识别单个项目风险，更全面地识别风险。

识别风险后，考虑轻重缓急，进行优先级排序。

## 定性风险分析（四步骤）
目的：给出一个靠谱的定性风险分析结果。

1. **风险概率和影响评估**：分析每个风险发生的概率和影响。
2. **风险数据质量评估**：评价分析出来的概率、影响数据可靠不可靠。数据可靠，评级依据才靠谱。使用低质量风险数据，会导致定性风险分析对项目没用。
3. **概率和影响矩阵**：查询每一个单一风险在矩阵里的位置，得到风险的优先级。
4. **其他风险参数评估**：考虑紧迫性、临近性、潜伏性、可管理性、可控性等，对风险的排序结果做调整。

## 规划风险应对

### 威胁应对策略 vs 机会应对策略
| 威胁（坏事） | 机会（好事） |
| --- | --- |
| 规避 | 开拓 |
| 减轻 | 提高 |
| 转移 | 分享 |
| 接受 | 接受 |
| 上报 | 上报 |

### 威胁应对策略详解
- **上报**：跟我没关系、不归我管、超出我的权限，影响到谁、谁有权管就找谁。项目团队或发起人认为某威胁不在项目范围内，或提议的应对措施超过项目经理权限时，就采用上报策略。威胁一旦上报，不再由项目团队做进一步监督，但仍可留在风险登记册中供参考。只做逻辑删除（做标记），不做物理删除，防止后期有人再发现此威胁、翻登记册无记录而再次上报。
- **规避**：采取行动消除威胁，把发生概率降到零。
- **转移**：把具体风险的归属和责任转移给第三方，通常需向承担威胁的一方支付风险转移费用。
- **减轻**：采取措施降低威胁发生的概率和/或影响，变成小概率事件。
- **接受**：承认威胁存在，但不主动采取措施。
  - 主动接受：事后仍有所准备，建立应急储备、准备好对应的应急计划。
  - 被动接受：纯躺平，没有任何措施，出了问题到时候再说。

### 机会应对策略
- **开拓 vs 提高（本质区别：量变到质变）**：开拓是把组织中最有能力的资源分配给项目来缩短工期，或采用全新技术/技术升级来节约成本、缩短项目持续时间——只要带形容词、性质上发生改变，就是开拓。
- **开拓 vs 分享（口诀）**：别人有好东西咱拿来用，叫开拓；咱有好东西给别人，叫分享。

### 应急应对策略
某些风险发生前会有信号、征兆预警，提前制定应急计划，出现信号时就执行这个应急计划。

## 监督风险
监督风险 = 查（结果）+ 计（过程），与审计/检查一样：

- **审计过程**：看风险管理这一堆管理过程（规划风险、识别风险、定性分析、定量分析、规划应对、实施应对）什么地方做得好、做得不好，总结经验教训，以便改进过程。
- **查结果**：应对措施好不好使，风险有没有发生变化。

**技术绩效分析**：技术绩效是否符合预期。

**风险审查会**：定期安排风险审查，一看风险应对措施的有效性，二做风险再评估——重新评估当前风险，看看有没有新风险、哪些风险可以关闭了、有没有发生变化、哪些风险过时了、已关闭的风险有没有死灰复燃。
